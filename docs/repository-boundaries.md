# BE · FE · AI 저장소 분리안

## 저장소 역할

### BE

- FastAPI 앱과 JSON API
- 회원가입, 로그인, 권한 확인
- PostgreSQL 스키마와 마이그레이션
- 학교·학과 공지 수집, 태깅, 추천
- FE와 AI가 사용할 API 계약 및 환경 설정

현재 코드: `app/main.py`, `app/auth/`, `app/db/`, `app/notices/`,
`app/crawler/`, `app/tagging/`, `db/`

### FE

- 웹 화면, 스타일, 브라우저 동작
- BE API를 호출해 인증 및 공지 데이터를 표시
- DB 접속 정보나 AI 제공자 키를 보관하지 않음

현재 코드: `app/templates/`, `app/static/`

현재 로그인·회원가입 화면도 Jinja 템플릿으로 BE가 렌더링한다. FE를 독립 실행하려면
이 화면을 FE로 옮기고, BE의 인증을 JSON API로 제공해야 한다. 로컬 개발에서는 FE가
BE API 주소를 환경변수로 받아야 한다.

### AI

- 질문과 BE가 선별한 공지 근거를 받아 답변 생성
- 답변, 사용한 공지 ID, 토큰 사용량을 BE에 반환
- 계정 인증, DB 접근, 크롤링은 맡지 않음

현재 코드: `app/chatbot/`의 후보 공지 타입과 LLM 제공자 어댑터. 아직 FastAPI에
연결된 챗봇 API가 없어서 독립 AI 저장소로 옮기기 전에 요청·응답 계약과 서비스
엔드포인트를 만들어야 한다. `app/notices/summarize.py`는 현재 규칙 기반 요약이므로
AI API 호출을 하지 않으며 BE에 둘 수 있다.

## 연결 방식

1. FE는 BE의 인증·공지 API만 호출한다.
2. BE가 사용자 권한을 확인하고 질문에 필요한 공지를 선별한다.
3. BE가 질문과 선별된 공지만 AI 서비스에 보낸다.
4. AI는 구조화한 답변과 근거를 BE에 반환한다.
5. 브라우저에는 BE 주소만 공개한다. AI API 키는 AI 서비스의 환경변수에 둔다.

별도 도메인으로 배포할 때는 BE에 허용할 FE origin을 설정하거나 같은 도메인 아래
reverse proxy를 둔다. 현재는 세 서비스가 한 앱 안에 있으므로, 저장소를 나눌 때
BE-기반의 통합 실행 설정도 함께 관리해야 한다.

## 현재 상태와 다음 연결 단계

- 현재 작업 폴더는 Git 저장소 하나이며 등록된 remote가 없다.
- `gh` 명령줄 도구가 설치되어 있지 않다.
- 코드 책임은 위 기준으로 나눌 수 있지만, GitHub에 저장소를 만들거나 push하려면
  GitHub 계정 연결과 대상 저장소가 필요하다.
- 목표 저장소를 연결한 뒤 FE 인증 API 분리, AI 서비스 엔드포인트 분리, 배포 환경변수
  및 통합 실행 설정 순으로 진행한다.
